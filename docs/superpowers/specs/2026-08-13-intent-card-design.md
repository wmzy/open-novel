# 意图采集与意图卡（Intent Card）设计

> 日期：2026-08-13
> 状态：待用户审阅
> 项目：open-novel

## 1. 背景与问题

当前 open-novel 的规划阶段（concept → outline → scenes）由 agent 基于 `.novel/` 设定文件生成大纲、伏笔与章节梗概。问题：

1. **AI 缺少作者深层意图**——设定文件表达"写什么"，但表达不了"怎么写"（节奏偏好、角色权重、伏笔风格、文风锚点等）。agent 生成时只能猜，猜错导致用户对产物不满意，只能推倒重来。
2. **现有 INTERVIEW_PROTOCOL 的采访答案不落盘**——答案散落在对话历史中，无法在新 run 中复用，也无法作为后续评审基准。

## 2. 目标

- 新增**意图卡**（`.novel/intent.md`）：作者创作偏好与意图的单一权威文档，AI 生成与修订时注入 prompt 作为硬约束，作者可随时手动编辑。
- 两条采集路径覆盖全生命周期：新建项目向导表单（快速初始化）+ 大纲阶段 agent 追问（深度补全）。
- 后续「意图符合度评审」功能直接复用本文件作为评审基准（本期不做）。

## 3. 非目标（本期不做）

- 意图符合度评审
- intent 结构化 JSON 权威源
- 意图卡版本历史
- 表单覆盖全部 8 维度（表单只做 4 个高频项，其余由 agent 追问补全）

## 4. 数据形态

文件路径：`.novel/intent.md`（与 concept/world/characters 同级）。

结构：8 个维度各一个 `##` 小节。每节内含固定条目，条目值为作者填写内容；未填写的维度条目统一标注「未设定」。

```markdown
# 作者意图卡

> 本文件记录作者的创作意图与偏好。AI 生成、修订、评审均以此为准。
> 可随时手动编辑；缺失维度用「未设定」标注。

## 节奏偏好
- 每章字数：未设定
- 张弛密度：未设定
- 断章钩子：未设定

## 角色权重
- 核心角色（弧线优先）：未设定
- 不可死亡角色：未设定
- 配角戏份上限：未设定

## 伏笔风格
- 长线/短线配比：未设定
- 埋设密度：未设定
- 回收节奏：未设定

## 文风锚点
- 语言密度：未设定
- 对话/描写比例：未设定
- 用词禁区：未设定

## 理念冲突偏好
- 理念冲突 vs 武力冲突比重：未设定
- 说教容忍度：未设定
- 理念呈现方式：未设定

## 多线叙事规则
- 单章视角数上限：未设定
- 线路切换频率：未设定

## 结局方向
- 基调：未设定
- 开放/闭合程度：未设定

## 叙事手法
- 倒叙/插叙容忍度：未设定
- 时间跳跃：未设定
```

设计约定：

- 「未设定」是一等状态，是 agent 追问环节的目标清单；
- 用户手动编辑优先级最高，agent 不覆盖已设定的维度；
- 意图卡描述"怎么写"，与 concept 设定文件（"写什么"）分工明确。

## 5. 采集流程

### 5.1 路径 1：新建项目向导表单

- `POST /api/projects` body 扩展可选字段 `intent`，仅含 4 个高频维度：`pacing`（节奏偏好）、`characterWeight`（角色权重）、`foreshadowStyle`（伏笔风格）、`styleAnchor`（文风锚点）。每个维度为纯文本字符串。
- 后端 `initWorkspace()` 生成 intent.md 初始骨架：表单提供值的维度写入，其余标「未设定」。
- 前端：新建项目对话框加「创作偏好（可选，可跳过）」折叠区，4 个文本输入。
- 每节长度上限 500 字，超长后端截断。
- 已有项目（如 ygj）不改创建流程，走路径 2 补采。

### 5.2 路径 2：大纲阶段 agent 追问

大纲阶段 prompt 在 INTERVIEW_PROTOCOL 之后注入新指令（INTENT_COLLECTION_INSTRUCTION），指令内联完整骨架模板（8 维度 + 「未设定」占位）：

1. 进入大纲阶段先读 `.novel/intent.md`（不存在则按指令内联模板创建骨架）；
2. 对「未设定」的维度，用提问工具（ask）逐维追问——选择题形式，每轮不超过 3 题，相关维度可合并一轮；
3. 追问结果写回 intent.md：写入前重读文件，**只更新自己追问过的维度小节**，不覆盖其他已设定内容；
4. 生成大纲时严格以 intent.md 为约束；
5. `autonomous` 模式跳过追问，直接用现有 intent.md 与维度默认值（默认值内联在提示词中）。

## 6. 注入策略

`src/agent/prompt-composer.ts` 新增 `buildIntentLayer(projectDir)`：

- 读取 `.novel/intent.md`，全量注入（预计 800-1200 字）；
- 注入位置：核心设定层之后、阶段指令之前，标题为 `## 作者意图（以此为准）`；
- 文件缺失或为空 → 跳过该层，run 不阻断（存量项目平滑过渡）；
- 所有运行模式注入：generate / revise / planMode / deepen。

## 7. 错误处理与边界

| 场景 | 行为 |
|---|---|
| intent.md 不存在 | 跳过注入；agent 追问环节先按指令内联的骨架模板创建，再追问 |
| intent.md 读取异常（权限/编码） | 跳过注入，run 不中断 |
| agent 写入与用户手动编辑并发 | agent 写入前重读，只更新自己追问过的维度小节 |
| 表单字段超长 | 后端按 500 字/节截断 |
| 空骨架直接进 autonomous | 使用提示词内联的维度默认值 |

## 8. 组件划分与改动面

| 单元 | 职责 | 依赖 |
|---|---|---|
| `src/shared/intent-card.ts`（新增） | 纯函数：表单数据 → markdown 骨架；解析/合并写回（agent 追问结果按维度更新）；默认值定义 | 无 |
| `src/agent/prompt-composer.ts` | 新增 `buildIntentLayer()` 注入意图层；新增 INTENT_COLLECTION_INSTRUCTION 常量 | intent-card.ts |
| `src/api/routes/projects.ts` | POST `/` 接收 `intent` 字段并传入 `initWorkspace()` | intent-card.ts |
| 前端新建项目对话框 | 「创作偏好」折叠区 4 个文本输入 | 无 |

## 9. 测试计划

- 单元（`tests/unit/shared/intent-card.test.ts`，新增）：
  - 表单数据 → markdown 骨架：给定值写入正确小节、未给值标「未设定」；
  - 合并写回：agent 只更新追问过的维度小节，不覆盖其他小节；
  - `buildIntentLayer`：文件缺失返回空层、文件为空返回空层、正常文件返回包装后的内容。
- 集成（`tests/integration/api.test.ts` 追加用例）：
  - 创建项目带 intent → `.novel/intent.md` 落盘内容正确；
  - 创建项目不带 intent → 不创建 intent.md（走追问路径）。

## 10. 验收标准

1. 新建项目（带 intent）后，`.novel/intent.md` 存在且表单维度已写入、其余维度标「未设定」；
2. 新建项目（不带 intent）不生成 intent.md，流程与现状一致；
3. 大纲阶段 run 的 prompt 包含「作者意图」层（文件存在时）；
4. intent.md 缺失/为空时，run 正常执行、prompt 无意图层；
5. 手工编辑 intent.md 后再次发起 run，prompt 反映手工编辑内容。
