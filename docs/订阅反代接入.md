# 订阅用户接入：本地反向代理（BYOK）

> 适用：已有 Claude Code / Codex / Copilot 等订阅，但不想再单独购买 API Key 的用户。
> 原则：open-novel 只使用**兼容 API**；不内置、不分发、不代管任何订阅反代。

## 1. 原理

Pi SDK 通过 `ModelRuntime` 调用 OpenAI/Anthropic 兼容接口。订阅本身通常不是标准 API，
因此需要在**本机**启动一个反向代理，把订阅转成下面两种协议之一：

- `openai-completions` / `openai-responses`
- `anthropic-messages`

```text
open-novel (Pi) → http://127.0.0.1:<port>/v1 → 本地反代 → 你的订阅
```

反代必须只监听 `127.0.0.1`。不要把端口暴露到局域网或公网，也不要把订阅凭据写进
open-novel 的数据库。

## 2. OpenAI-compatible 反代

假设反代监听 `http://127.0.0.1:8080`，提供 `POST /v1/chat/completions`：

| 设置项 | 填写 |
|---|---|
| Provider | 自定义 / 本地反代 |
| 模型 ID | 反代声明的模型名，例如 `claude-sonnet-4-5` |
| API Base URL | `http://127.0.0.1:8080/v1` |
| API 协议 | `openai-completions` |
| API Key | 反代要求时填写；本地无鉴权可留空 |
| 思考等级 | 按需（off/low/medium/high/max） |

保存后点击「测试配置」；`/api/agents` 应返回 `available: true`。

## 3. Anthropic-compatible 反代

如果反代直接暴露 Anthropic Messages 协议：

| 设置项 | 填写 |
|---|---|
| Provider | Anthropic（或自定义） |
| 模型 ID | 订阅实际允许的模型 ID |
| API Base URL | 反代根地址，例如 `http://127.0.0.1:8080` |
| API 协议 | `anthropic-messages` |
| API Key | 反代要求时填写 |

> 选择内置 `Anthropic` provider + 自定义 Base URL 时，open-novel 会保留 Pi 的
> Anthropic 模型目录，只替换 endpoint。模型 ID 仍须与反代实际支持的名称一致。

## 4. Ollama / LM Studio（本地模型）

```text
Provider: 自定义 / 本地反代
Model:    qwen3:14b
Base URL: http://127.0.0.1:11434/v1
API:      openai-completions
API Key:  留空
```

Ollama 的原生 `/api` 端点不是 OpenAI-compatible；必须使用 `/v1`。

## 5. 验证

```bash
# 配置可解析（不产生生成费用）
curl -s -X POST http://127.0.0.1:3006/api/agents/pi/test | jq

# 模型列表
curl -s http://127.0.0.1:3006/api/agents/pi/models | jq

# 实际写作：在项目对话面板发一条消息，观察 SSE 文本/工具事件
```

如果 `test` 返回 `auth: missing`：

- 内置 provider：检查 API Key 是否已保存，或对应环境变量是否设置；
- 自定义 provider：检查 Base URL、模型 ID、API 协议；
- 本地反代：确认进程仍在监听，且 open-novel 与反代在同一网络命名空间。

## 6. 安全与合规

- 反代只绑定 `127.0.0.1`；open-novel 默认也只绑定 `127.0.0.1`。
- 不要把订阅 Cookie、OAuth Token 或反代密钥写进项目目录、git 仓库或日志。
- 订阅转 API 可能受服务商条款限制；请自行确认允许的用法与额度。
- open-novel 不提供反代实现，也不对第三方反代的稳定性/合规性负责。
- 需要多人使用时，优先使用标准 API Key，而不是共享个人订阅反代。
